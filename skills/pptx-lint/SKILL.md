# pptx-lint

対象の資料を次の手順で検証し、指摘だけを返す。会話の履歴は前提にしない。修正はしない。

## 手順

1. **対象を決める**。呼び出し文にディレクトリの指定があればそれ。無ければ、カレントディレクトリから `deck.json` と `deck-src/` を持つディレクトリを探す（カレント自身、次に直下の子）。見つからなければ「対象の資料が見つからない」と 1 行で返して終わる
2. **PNG を用意する**。出力名は `deck.json` の `name`（呼び出し文に `--name` があればそれ）。`preview/<name>-NNN.png` が無い、または `<name>.pptx` より古ければ `node build.js --name <name>` を実行する。ビルドが規格違反で止まったら、その出力を指摘として返す
3. **範囲を決める**。呼び出し文に `--pages 3-5` のような指定があればそのページだけ、無ければ全ページ
4. **1 枚ずつ読む**。PNG を Read し、下の観点で検査する。PDF や pptx は読まない
5. **返答の形式で返す**。所感・称賛・修正案の本文は書かない

## 検査の観点

文章と構成の規範は、使っている書式スキルが持つ。所定の青基調なら [../ms-format/writing-rules.md](../ms-format/writing-rules.md) が正本。迷ったらそれに従う。
書式スキルを使っていない場合は、レイアウト・描画・色の 3 種別だけを見る。

| 種別 | 見るもの |
|---|---|
| レイアウト | 文字のはみ出し、意図しない折り返し、要素の重なり（後から描いた枠がテキストを隠している）、出典行の折り返し、本文領域の下端からの逸脱、余白が大きすぎる（情報不足） |
| 描画 | 文字化け（豆腐）、アイコンの欠落、細すぎて消えた線、文字が小さすぎて読めない |
| 色 | 青系・白・グレー以外の色の混入、赤が 1 枚に複数箇所、並列する項目の 1 つだけの着色、補足や結論を囲む色付きの枠、表のデータ行の塗り |
| 階層 | タイトルが体言止めでない、キーメッセージがですます調の完全文でない（1 文なら句点なし、2 文なら 1 文目だけ句点）、本文がである調でない、＜見出し＞が短い名詞句でない・個数入り・直下に一文が無い |
| 構成 | 下部のまとめ帯やキーメッセージの再掲、章番号・他スライド・資料自体への言及、図の下の説明文、本文での図の名指し、数の言い切り、口語・比喩・造語、一直線のフロー図、番号の対応先が無い、対比が左右非対称 |

## 返答の形式

1 行目は集計。2 行目以降は指摘を 1 行ずつ。指摘が無ければ「指摘なし」の 1 行だけ。

```
9 ページ中 3 ページに 4 件
p4: 出典行が 2 行に折り返し、本文と重なる（レイアウト）
p4: ＜守る原則＞の直下に説明の一文が無い（階層）
p7: 戻りの矢印のラベルが破線と重なる（レイアウト）
p9: 本文に「図のとおり」と図の名指しがある（構成）
```

ページ番号は PNG のファイル名の番号。同じページに複数あれば行を分ける。
