# image-to-pptx スキル

画像 1 枚のスライドを、編集できる pptx に再構成する。テキストはテキストボックス、帯やカードは図形、アイコンは正規アイコンで置き、レンダリング比較で崩れを直してから納品する。スライド全体を 1 枚の画像として貼らない。

**変換元の画像は 2 通りの経路で用意する。**

| 変換元の画像 | 進め方 |
|---|---|
| 指定されている（他社の資料、過去の PDF、受け取ったスクリーンショット） | 画像生成を経由せず、その画像をそのまま入力にする |
| 指定されていない | 画像生成 MCP `slide-image-gen` を呼んで 1 枚生成し、それを入力にする |

MCP が導入されていない環境では、図の構成を会話で決め、[../content-to-pptx/SKILL.md](../content-to-pptx/SKILL.md) で図形とアイコンから直接作る。
登録済みなのに接続できない場合は、**REST を自分で組み立てて呼ばない**。起動コマンドのパスと接続先の設定を確かめて直すか、上の手順に切り替える。

**書式・描画ヘルパー・ビルドは、プラグイン直下の共通の雛形（`template/`）にある。** 変換の成果物もこの雛形の上でビルドする。

## 書式の決め方

1. 会話で明示されたテーマ（ファイルパス）
2. 参考画像から `scripts/extract_style.py` で抽出し、利用者が確認したテーマ（後述）
3. 作業ディレクトリの `deck-src/theme.json`。書式スキルを併用していれば、その書式が適用済みになっている

「元画像の書式をそのまま」「このブランドに合わせる」と指示されたときは**忠実モード**にし、各要素の色・サイズ・位置の実測値をそのまま渡す（ヘルパーはどれも座標と色を引数で受け取るので、テーマを介さずに置ける）。
どちらのモードでも、編集可能性の検証・レンダリング比較・規格の正規化は同じに行う。

## 作業ディレクトリ

変換ごとに 1 つ切る。プラグイン直下の `template/` をコピーし、入力と切り出しの置き場を足す。
書式スキルを併用する場合は、コピー直後にそのスキルの手順で書式を適用してから始める。

```
<work>/
├── source/            入力画像（コピー）と grid-overlay.png
├── assets/icons/      アイコン（書式スキル由来）と追加取得分
├── assets/crop/       元画像から切り出した図版
├── deck-src/<name>.js 生成するスライドの定義
└── preview/           レンダリング結果と compare.png
```

添付された画像はファイルの実体が無いことがある。最初に `source/` へ保存してもらう。以降の座標把握・切り出し・比較には実ファイルが要る。

## ワークフロー

1. **入力を用意する**: 変換元の画像を `source/` に置き、書式を上の順序で決める。
   - **画像が指定されている場合**は、それを `source/` にコピーする。画像生成は呼ばない
   - **画像が指定されていない場合**は、画像生成 MCP `slide-image-gen` を呼んで 1 枚生成し、`source/` に置く。プロンプトは書式の `imagePrompt` と `colors` から組み立てる（書式スキルを併用していれば、その定義にある）
2. **座標把握**: `uv run <このスキル>/scripts/grid_overlay.py source/<img>.png source/grid-overlay.png` を実行し、出力画像を表示して各要素の px 矩形を読み取る。目測より正確になる。
3. **要素分解**: テキスト / 図形 / 矢印 / 記号 / アイコン / 表に分け、px 矩形と色・文字サイズの当たりを付ける（後述の換算式と対応表）。
4. **テキスト転記**: 誤字・全角半角・記号・数字・単位を元画像に一致させる。言い換えや要約はしない。
5. **アイコンと図版**: 作業ディレクトリのアイコン（`assets/icons/`）で足りなければ `assets/icons/icons.json` に足して `uv run tools/fetch_icons.py` で取得する。正規アイコンで代用できない独自の図版・写真だけ切り出す。

   ```bash
   uv run <このスキル>/scripts/crop_assets.py source/<img>.png assets/crop \
     '[{"name": "diagram", "box": [793, 164, 1016, 496], "autotrim": true}]' --map assets/crop/placement.json
   ```

   矩形は広めに取って `autotrim` に詰めさせる。近接するラベル文字を矩形に含めない（含めると編集できない文字になる）。`--map` が出す px 矩形と同座標・同サイズで配置すれば位置が合う。
6. **pptx 生成**: `deck-src/<name>.js` にヘルパーで定義し、`deck.json` の `parts` を差し替えて `node build.js --name <name>` を実行する。しおり名・規格の正規化と検査・PDF・PNG まで済む。
7. **レンダリング比較**: `uv run <このスキル>/scripts/render_and_compare.py <name>.pdf preview --source source/<img>.png` で `preview/compare.png` を作り、元画像と上下に見比べる。
8. **補正**: 崩れを直して 6〜7 を繰り返す。**最低 1 回は補正する。**
9. **検証と納品**: `uv run <このスキル>/scripts/inspect_pptx.py <name>.pptx --json validation.json` で警告 0 を確認する。続けて、**全ページの体裁と文章規範の検査は [../pptx-lint/SKILL.md](../pptx-lint/SKILL.md) に任せる**（作業ディレクトリを添えて呼ぶ）。`inspect_pptx.py` が見るのは編集できるかどうかだけで、崩れと規範は見ていない。pptx と同名の PDF も添える。

## 座標と単位の換算

スライドは 13.33 × 7.5 inch（16:9）。元画像が 16:9 なら縦横共通の係数 1 つで変換できる。

```
K = 13.33 / 画像の幅px          inch = px × K
pt ≒ 文字の高さpx × 540 / 画像の高さpx     （スライド高 7.5 inch = 540 pt。漢字は字面がほぼ em）
```

元画像の比率が 16:9 でないときは、比率を保つか 16:9 に収めるかを利用者に確認する。文字サイズは最後にレンダリング比較で詰める。

## 要素の対応

| 元画像の要素 | 変換先 | ヘルパー |
|---|---|---|
| タイトル / キーメッセージ / 見出し / 本文 / 注釈 | テキストボックス | `title` `keymsg` `sec` `BODY` `CAP` `T` |
| 帯・カード・角丸ボックス・番号バッジ | 図形 | `BOX` `OVAL` `PILL` `TAG` |
| 矢印（実線・破線・双方向） | 矢頭付きの線 | `ARROW` |
| 罫線・区切り線 | 線 | `HLINE` `VLINE` |
| ✕ ✓ などの記号 | テキスト（編集できる方を優先） | `T` |
| アイコン・イラスト | 正規アイコンの PNG、無ければ切り出し | `ICON` `IMG` |
| 表（行列が明確） | ネイティブの表 | `TBL` `cell` `hOpt` |
| コード・設定例 | コードボックス | `CODE` |
| 写真・複雑な図版 | 切り出した PNG | `IMG` |

## 守るべき要点

- **スライドを 1 枚画像にしない。SVG を埋め込まない。** `inspect_pptx.py` が検出して警告する。
- 矢印や線の `w` / `h` に負の値を渡さない。右から左・下から上へ引くと出る。PowerPoint はそのファイルを開けないが、LibreOffice も PDF も通してしまう。ヘルパーの `ARROW` を使い、`tools/normalize.py --check` を常に 0 件にする。
- テキストは折り返さない幅にする。細い線は 2.5〜3pt 以上にする（レンダリングの縮小で消える）。
- 正規アイコンは正方形なので、元の矩形に短辺基準で中央フィットさせる。切り出しは元の px 矩形と同座標・同サイズで置く。
- 白背景の切り出しは透過にする（既定のしきい値 248）。文字が焼き込まれた図版は、文字を切り出しから外して別のテキストで重ねる。
- 表やグラフで完全な編集化が難しい部分は画像にフォールバックし、`validation.json` か報告に書く。
- フォントは単一名しか指定できない。日本語は環境にあるもの（Yu Gothic UI / Meiryo UI / Noto Sans CJK JP）を選ぶ。字形の差で折り返しが変わるため、最終確認はレンダリング比較で行う。

## 参考画像から書式を起こす

書式だけを参考画像から取り、別の内容に適用したいときの手順。

```bash
uv run <このスキル>/scripts/extract_style.py source/reference.png build/style \
  '{"title": [60, 40, 1700, 120], "keyMessage": [60, 140, 1700, 230], "body": [60, 260, 1700, 960]}'
```

1. 領域の px 矩形は `grid_overlay.py` で読む。省略すると帯を自動検出する。
2. `build/style/theme-draft.json`（草案）と `swatches.png`（色見本）ができる。色と幾何は画素から推定した値なので、そのまま信じない。
3. フォントは画素から復元できないため既定値が入る。字形から候補を挙げて利用者に確認する。
4. 草案を `deck-src/theme.json` に置いて見本をビルドし、`render_and_compare.py --source source/reference.png` で並べて詰める（3 往復が目安）。

## 同梱スクリプト

`uv run` で実行すると依存（Pillow / PyMuPDF / python-pptx）が自動で入る。pip で入れてあれば `python3` でもよい。

| スクリプト | 役割 |
|---|---|
| `scripts/grid_overlay.py` | 座標把握用のグリッド画像 |
| `scripts/crop_assets.py` | 矩形の切り出し（白背景の透過、`autotrim`、`--map`） |
| `scripts/extract_style.py` | 参考画像から theme.json の草案とスウォッチ |
| `scripts/render_and_compare.py` | pptx / PDF → 全ページ PNG、元画像との比較画像 |
| `scripts/inspect_pptx.py` | 編集可能性の検証（全面画像・SVG・テキスト 0 件を警告） |

書式の値とヘルパーの引数は [../../template/README.md](../../template/README.md)、pptxgenjs の落とし穴は [../../references/pptxgenjs.md](../../references/pptxgenjs.md)、環境の点検は [../env-setup/SKILL.md](../env-setup/SKILL.md)。
