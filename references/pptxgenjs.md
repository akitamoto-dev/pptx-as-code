# pptxgenjs の技法と落とし穴

`lib.js` のヘルパーはここに書いた対策を組み込んである。ヘルパーを追加・修正するときと、原因不明の崩れを調べるときに読む。

## レイアウト

組み込みの `LAYOUT_16x9` は 10 x 5.625 inch で、PowerPoint 既定の 13.33 x 7.5 と異なる。フォントサイズは絶対単位（pt）なので、キャンバスが小さいと文字が相対的に大きく見える。`build.js` は `theme.json` の `layout` で `defineLayout` する。

## 負のサイズ（PowerPoint で開けなくなる）

始点と終点から `w: x2 - x1, h: y2 - y1` と計算すると、右から左・下から上へ引いた線で幅や高さが負になる。pptxgenjs はそのまま `<a:ext cx="-877824">` と書き出すが、OOXML ではサイズは非負と定められており、PowerPoint はファイル全体を破損と判定して開けなくなる。LibreOffice と python-pptx と zip の検証はすべて通過するため、PDF を確認しても気づけない。

`ARROW` は外接矩形を正の値で与え、向きを `flipH` / `flipV` で表す（見た目は同じ）。ヘルパーを経由しない直書きからの漏れは `tools/normalize.py` が直す。
負のサイズを含んでいても開けるファイルはあるため、「他のファイルでは問題が無かった」ことを根拠に無視せず、常に 0 件にしておく。

## normalize が直すもの

| 違反 | 内容 |
|---|---|
| 負のサイズ | 外接矩形を正にし、flipH / flipV で向きを表す |
| 図形 ID の重複 | 同じスライド内の `cNvPr/@id` を振り直す |
| 実体のない Override | `[Content_Types].xml` が宣言する存在しないパートを消す |
| zip のディレクトリエントリ | OPC に含めてはいけないフォルダエントリを消し、`[Content_Types].xml` を先頭に置く |
| 同一段落内の重複する段落設定 | 同じ内容の `a:pPr` が並んだら先頭だけ残す。内容が異なる場合は自動で統合せず止まる |

最後の項目は、1 つの段落を複数の run で作るとき（部分着色、文中リンク）に起きる。pptxgenjs は run ごとに段落設定を書き出すため、同じ段落に属する run には同じ段落レベルのオプション（`paraSpaceAfter`、`align`、`bullet` など）を与える。`BULLETS` はこのために項目内の全 run に同じ設定を付けている。

原因が特定できないときは、構成要素を 1 種類ずつ取り除いた版（リンク・画像・表・負のサイズをそれぞれ除去）を作って PowerPoint で開き、1 往復で切り分ける。ページ範囲の二分探索より速い。

## 描画順

要素は `addShape` / `addText` / `addImage` の追加順に重なり、後に追加したものが前面に来る。ゾーンや背景の色付きボックスは、その中に載せる要素より先に描く。

## フォント

`fontFace` には単一のフォント名しか指定できず、フォールバックは書けない。**pptx に入るのは名前だけで、実際に描画するのは開いた人の PowerPoint。** 手元にそのフォントが無くても pptx は正しく、影響するのは LibreOffice が描く PDF と PNG の見た目だけになる（`build.js` が警告する）。`theme.json` の `fonts.fallback` は、本命が無い環境で何に置き換わるかの記録であり、`fonts.body` を差し替えるための候補ではない。
デッキ既定のフォント（`ppt/theme/theme1.xml`）は `build.js` が本文フォントに揃える。ヘルパーが描くテキストは全 run に `fontFace` が入るため影響しないが、PowerPoint で後からテキストボックスを足したときの既定になる。
Linux に Consolas は無いため、PDF のコードは DejaVu Sans Mono 等で描画される。PDF は確認用と位置づけ、見た目の最終確認は PowerPoint で行う。

## オプションオブジェクト

pptxgenjs はオプションオブジェクトを内部で書き換える。同じオブジェクトを複数の要素に渡すと別の要素に影響が出るため、定数として持つ場合はファクトリ関数で毎回新しいオブジェクトを返す。`cell` が毎回新しいオブジェクトを作るのはこのため。

## 表

- 罫線は pt、セルの余白 `margin` は `[上, 右, 下, 左]` の pt（inch ではない）
- `colW` の合計が表の幅になる。`rowH` は数値か配列。省略すると `rowH()` が文字幅から見積もる
- 日本語の倍率行間で行が伸びて PDF が広がる場合は、各 run に固定ポイントの `lineSpacing` を与える
- 文中リンクは run を分け、全 run に同じ `fontSize` を付ける。リンク run は青と下線（`LINK`）。リンクのためだけに改行や別ラベルを入れない。段落設定が重複するので normalize を通す

## PDF のしおり

各スライドの内部名 `<p:cSld name>` は既定で `Slide 1, Slide 2…` で、LibreOffice の PDF 変換はこれをしおり（アウトライン）名に使う。`build.js` は PDF 変換の前に、`title` が記録した `__pdftitle` で書き換える。`title` を使わずに作ったスライドはしおり名が既定のままになる。

## LibreOffice

既定ではユーザープロファイルを共有するため、複数の作業ディレクトリから同時に変換すると片方が無言で失敗する（終了コード 1、PDF 無し）。`build.js` は `-env:UserInstallation` で作業ディレクトリ配下にプロファイルを分離しているので、soffice を直接呼ばない。

## 文字幅の概算

半角を 0.48em、全角を 1.0em として `widthIn(文字列, pt)` が幅（inch）を返す。`title` の自動縮小、`rowH` の行数見積もりがこれを使う。
出典行は本文幅で全角約 95 字が 1 行の上限。半角英数は全角の 0.6 掛け程度で換算し、見積もりは余裕を持たせる。超えると折り返して上の要素と重なる。
